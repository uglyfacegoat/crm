# Почта компании и копии сотрудникам

## Подтверждение входа кодом

У каждого сотрудника есть вкладка **Настройки → Безопасность**. Для включения защиты
нужно подтвердить адрес кодом из письма; для отключения требуется текущий пароль.
Смена собственного пароля завершает другие сеансы.
После верного пароля защищённой учётной записи CRM создаёт десятиминутный запрос, а почтовый worker отправляет
семизначный код на почту самой учётной записи. Полноценная сессия возникает только
после верного кода; пять неверных попыток закрывают запрос. Код не хранится в открытом
виде и не допускает повторного использования. Это подтверждение доступа к email,
а не независимый аппаратный фактор.

На сервере инфраструктура отправки пока выключена (`smtpReady=false`, `AUTH_EMAIL_OTP_ENABLED` не задан).
Кнопка подключения остаётся недоступной, пока почта не готова. Для запуска нужны достижимые личные адреса сотрудников,
исходящая доставка с доверенным TLS и тестовым письмом наружу, одинаковый новый
`AUTH_EMAIL_OTP_SECRET` в web и mail-worker и `AUTH_EMAIL_OTP_ENABLED=true` в обоих.
После перезапуска mail-worker проверить свежий успешный heartbeat с `otpReady=true`,
затем подключить защиту тестовой учётке через письмо и пройти полный вход в отдельном браузере. Если защита уже включена, но worker/SMTP перестали работать,
пароль не выдаёт сессию: вход отвечает временной недоступностью и остаётся закрытым.

## Схема

Один принадлежащий нам почтовый сервер обслуживает несколько доменов. Для каждого сайта создаётся настоящий отдельный ящик: сейчас `info@tehstroinvest.ru`, позже, после настройки домена, например `info@bio-save.ru`. Это не алиасы одного ящика. В CRM письма всех подключённых ящиков попадают в общую ленту с указанием получателя и фильтром по ящику. Адреса и привязки к сайтам хранятся в `mail_sources`.

Сотрудник может добавить личный email, подтвердить его ссылкой и отдельно для каждого источника выбрать копии заявок и входящих писем. Сами письма и заявки остаются в CRM. Внутренний чат в рассылке не участвует. Workflow и помощник временно выключены.

## Текущее состояние (25.09.2026)

На текущем VPS `188.127.249.187` установлены Postfix, Dovecot и OpenDKIM, создан `info@tehstroinvest.ru`. Сайт отправляет уведомления о заявках в этот ящик через локальный SMTP `127.0.0.1:2525`. CRM mail-worker забирает письма по IMAP с проверкой временного сертификата, но без исходящего SMTP. Проверка заявкой `TSI-20260925-EC8BE4F2` прошла по цепочке сайт → CRM → реальный ящик → общая лента CRM. Старый почтовый VPS `87.251.78.28` недоступен; старые письма без его резервной копии перенести нельзя.

Внешняя почта **ещё не включена**: DNS `mail.tehstroinvest.ru` и SPF/DKIM указывают на старый сервер, MX отсутствует, на новом VPS пока временный самоподписанный сертификат. Фоновый `mail-worker` CRM включён только для приёма писем с локального ящика; исходящие копии и подтверждение личных адресов выключены до настройки DNS, выпуска доверенного сертификата и сквозной проверки получения/отправки. Заявки с сайта поступают в CRM независимо от почты.

## Что нужно для включения `tehstroinvest.ru`

1. В REG.RU изменить A `mail` на `188.127.249.187`; добавить MX `@` с приоритетом 10 на `mail.tehstroinvest.ru.`; обновить SPF `@` на `v=spf1 ip4:188.127.249.187 -all`; добавить TXT `mail2026._domainkey` с публичным ключом, сформированным на сервере. Старый `mail._domainkey` можно удалить после проверки, что он нигде больше не используется. DMARC уже есть.
2. Попросить SmartApe назначить PTR для `188.127.249.187` → `mail.tehstroinvest.ru` и проверить открытый входящий TCP 25, а также возможность исходящих соединений SMTP. PTR устанавливает владелец IP, не REG.RU.
3. После обновления A выпустить сертификат Let's Encrypt для `mail.tehstroinvest.ru`, поставить его в `/etc/tehstroinvest-mail/tls` и настроить обновление. Не включать mail-worker с временным самоподписанным сертификатом.
4. Проверить реальный входящий email из внешнего ящика, DKIM-подпись и доставку исходящего письма наружу. Проверить, что Postfix не допускает открытую ретрансляцию.
5. Источник `info@tehstroinvest.ru` и приватный `/opt/crm-deploy/.env.production.mail` уже созданы. После установки доверенного сертификата убрать временное доверие к самоподписанному сертификату и добавить SMTP-параметры для исходящих писем; пароль ящика хранится на сервере в `/etc/tehstroinvest-mail/mailboxes`, не в Git.
6. Проверить входящее письмо извне в общей ленте, затем подтверждение личного адреса сотрудника и копии отдельно для выбранных источников.

Новые домены добавляются скриптом `tehstroinvest-site/deploy/mail/add-mailbox.sh`. Их MX может указывать на тот же `mail.tehstroinvest.ru`; каждому домену нужны собственные MX/SPF/DKIM/DMARC записи. Новый почтовый хост и отдельный TLS-сертификат для каждого домена не обязательны. Код CRM принимает несколько IMAP-ящиков через `CRM_MAIL_ACCOUNTS_JSON`. Пока точный домен Bio Save не подтверждён, никакие его DNS-записи или ящики создавать не надо.
