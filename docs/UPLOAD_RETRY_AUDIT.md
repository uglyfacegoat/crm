# Повторы и неопределённый результат загрузок (UP-07, в работе)

24 сентября 2026. Девять пользовательских потоков перечислены в [карте записи файлов](STORAGE_WRITERS.md). `UP-07` пока открыт: отмена браузерного запроса и потерянный ответ в момент commit на настоящем runtime/БД ещё не проверены для каждого семейства.

Что подтверждено сейчас:

- `scripts/upload-commit.check.mjs` проверяет документ, версию, чек оплаты и чек выплаты. При ошибке после подтверждённого commit файл остаётся и интерфейс сообщает о сохранении с требованием обновить страницу. При известном отказе откатывается только принадлежащий запросу файл; при неизвестном исходе байты сохраняются до сверки. Повтор уже подтверждённой операции не читает и не записывает файл снова.
- `scripts/upload-lifecycle.check.mjs` проверяет акт, фото выезда, шаблон, вложение и фото группы на те же исходы commit/отказа, `EEXIST` и сохранение прежнего фото группы. Для первых четырёх дополнительно подтверждено, что повтор принятого запроса не читает и не записывает файл снова. Текущие проверки используют управляемые подмены репозитория и файлового адаптера.
- `scripts/uploads-browser-check.mjs` на собранном сервере проходит все девять потоков с нормальным сохранением и с ошибкой обновления интерфейса после commit. Два одинаковых Server Action POST одновременно проверены для всех девяти потоков: по одной ожидаемой записи и версии файла, правильные байты; прежняя версия документа остаётся доступной, выезд завершается один раз. Ответы возвращают успех либо сообщение об обработке/конфликте. Все эти сценарии прошли с локальным и тестовым S3-хранилищем. Обрыв сети в момент commit этим прогоном пока не покрыт.
- При перегрузке двух слотов обработки браузер получил ошибку до записи и сохранил idempotency key. Формы нового документа и новой версии сохранили название/комментарий и выбранный файл: после освобождения слотов повтор без повторного заполнения успешно сохранил один документ и ровно по одной записи каждой версии.
- Чек оплаты и чек выплаты также проверены при занятых слотах: отказ не создал финансовую запись или документ, а формы сохранили ключи, сумму, реквизиты, комментарий и файл. Повтор после освобождения слотов создал по одной финансовой записи и одному чеку с проверенными байтами.
- Фото выезда и подписанный акт проверены под учётной записью мастера. При занятых слотах отказ не создаёт документ и не завершает выезд; формы сохраняют ключи, комментарии, название акта и выбранные файлы. После повтора оба файла сохранились по одному разу, выезд завершился, байты совпали.
- Шаблон, вложение сообщения и фото группы также прошли отказ при занятых слотах и повтор на собранном сервере. Шаблон и группа сохранили файл и текстовые поля; существующая защита черновика чата сохранила текст, файл и ключ сообщения. До повтора записи не появились, после повтора каждая запись и её файл появились один раз, байты совпали. Таким образом сохранение полей при этом конкретном исправимом отказе проверено для всех девяти потоков. Другие причины отказа и неизвестный исход записи остаются открытыми.
- Для нового документа, новой версии, оплаты, выплаты, шаблона и вложения чата браузерный тест потерял ответ **после** успешного Server Action commit. Отдельная вкладка сохранила форму или черновик, файл, поля и idempotency key, показала сообщение о проверке истории; повтор исходного POST и повтор через интерфейс оставили по одной ожидаемой записи и версии файла с правильными байтами. У документа после повтора остались обе версии, а в чате — одно сообщение с одним вложением. Все шесть сценариев прошли с local и тестовым S3. До исправления обрыв при новом документе открывал общий экран ошибки и закрывал форму. Остальные три файловые формы и отмена запроса до/во время commit ещё не проверены на настоящем runtime.

Особый случай фото группы: запрос опирается на версию настроек канала. Два одновременных одинаковых запроса оставили одну версию настроек и один аватар на local и тестовом S3; проигравший может получить конфликт и просьбу обновить группу. Это не дублирует файл, но автоматического распознавания уже принятого повтора нет. Перед изменением поведения нужно сопоставлять сохранённый ключ и checksum, не принимая за свой результат чужое изменение настроек.

Для закрытия `UP-07` осталось воспроизвести обрыв/отмену до и во время commit, а также потерю ответа после commit для остальных трёх потоков на настоящем runtime с одноразовой БД; сверить таблицы, версии и байты файлов после повторов. В неизвестном исходе нельзя удалять файл только потому, что клиент не получил ответ.
