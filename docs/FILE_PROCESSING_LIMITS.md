# Конкурентная обработка файлов — UP-05 (частично)

24 сентября 2026. Загрузка файла уже ограничена 15 МиБ, но разбор PDF/изображений, антивирус и ZIP-экспорт одновременно расходуют память. [Общий слот](../src/server/file-scan/processing-slots.ts) использует два отдельных advisory-lock ключа PostgreSQL: один тяжёлый upload или экспорт занимает один ключ на время проверки и записи либо чтения и сборки архива. Поэтому два web-процесса с общей БД видят один предел. При занятых слотах новая загрузка не создаёт файл/строку БД и показывает сообщение о повторе, экспорт возвращает HTTP 429 с `Retry-After: 3` до чтения файлов и записи audit-события. Слот освобождается после успеха и ошибки.

Проверки: интеграционный сценарий удержал два слота через разные пулы PostgreSQL, третий запрос получил отказ; после освобождения и после исключения слот снова доступен. Браузерный сценарий на собранном сервере удержал оба слота, получил 429 на экспорт и отказ загрузки без записи. После освобождения слотов формы документа и новой версии сохранили ключ повтора, поля и выбранные файлы; повтор без заполнения создал один документ и ровно по одной записи каждой версии. Остальные 19 загрузок, девять предупреждений после commit и файл ровно 15 МиБ прошли. Финансовая интеграция прошла 28 проверок. Всё выполнялось на одноразовой БД; рабочая CRM не обновлялась.

Ограничение текущего решения: тело запроса уже может быть принято Next.js до получения слота, поэтому параллельные входящие 15-МиБ запросы всё ещё занимают память. Ответ архива также остаётся в памяти после освобождения слота до передачи клиенту. Пока не ограничены отдельные скачивания/preview и конкурентность чтения файлов для других сценариев. Нет замера RSS, задержек и временных файлов под нагрузкой на выбранном сервере. Значение «два слота» консервативное для кандидатной версии, а не доказанная ёмкость будущего сервера. UP-05 остаётся открытым.
