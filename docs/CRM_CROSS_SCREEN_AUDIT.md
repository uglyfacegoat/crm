## Правила для реализации

1. Общий UI-компонент выбирает услугу с поиском и единым визуальным стилем. Он не рассчитывает цену внутри себя: расчёт выносится в общую функцию, используемую всеми формами.
2. Сервер валидирует обязательность один раз на уровне общего сценария. Обязательный минимум заказа — заказчик. Дополнительные данные проверяются только если введены. Клиентская проверка отражает серверную, а не вводит новый набор обязательных полей.
3. Договорная ставка объекта выше базовой цены справочника; обе цены показываются с единицей измерения. Неизвестная цена остаётся неизвестной, а не маскируется нулём без признака `price_pending`.
4. Проходить каждую форму в ширинах 390, 768 и 1440 px; проверять клавиатуру и раскрытые меню. Для модалок дополнительно проверять вертикальное переполнение и сохранность кнопок действий.
5. После исправления одной сущности искать другие места её создания/редактирования и обновлять их до завершения работы.
