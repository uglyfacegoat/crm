# CRM — план разработки

Обновлено: 29 августа 2026

Этот файл — рабочий источник правды по реализации. Мастер-план описывает продукт, а здесь фиксируются порядок разработки, принятые решения и фактический статус.

## Статусы

- `[x]` — сделано и проверено;
- `[~]` — выполняется;
- `[ ]` — не начато;
- `[?]` — нужно бизнес-решение перед реализацией.

## Принятая архитектура

- Full-stack: Next.js 16, React 19, TypeScript, App Router.
- UI: Tailwind CSS 4, собственные компоненты и дизайн-токены.
- БД: PostgreSQL 17; локальное окружение описано через Docker Compose.
- Доступ к БД: SQL-first migrations + `postgres.js`; ORM пока не добавляется, чтобы не создавать второй слой до стабилизации доменной модели.
- Валидация внешних данных: Zod на серверных границах.
- Авторизация: серверные сессии, роли и проверка прав на уровне каждого ресурса.
- Файлы: закрытый storage-адаптер с постоянным Docker volume; в PostgreSQL хранятся метаданные, версии и связи. Интерфейс адаптера готов к замене на S3-compatible storage без миграции доменных данных.
- Деньги: целые значения в копейках в БД; валюта хранится явно.
- Финансовая первичка хранится отдельными строками: услуги, выплаты мастерам, дополнительные прямые расходы и платежи. Итоговые показатели считаются из этих данных, а не вводятся повторно вручную.
- Показатель `Операционный остаток компании` равен сумме заказа за вычетом выплат мастерам и дополнительных прямых расходов. Это не бухгалтерская чистая прибыль: налоги, постоянные расходы и прочие затраты в него не входят.
- Даты: время в UTC, date-only отдельно, отображение в рабочем часовом поясе компании.
- Удаление бизнес-данных: soft delete и audit log; физическое удаление — отдельная административная операция.
- Первая мобильная версия: адаптивный web + PWA, без отдельных iOS/Android приложений.

## Ближайший следующий шаг

Следующий backend-шаг — готовые шаблоны актов и завершение выезда из мобильной карточки с обязательным закрывающим документом. Параллельно развиваем чат: вложения через единое хранилище документов, изменение состава группы и системные сообщения о предстоящих выездах. Затем — загрузка новой версии документа, полное дерево архива и пользовательская лента истории переноса/отмены. UI продолжаем полировать по одной странице на основе присылаемых референсов.
